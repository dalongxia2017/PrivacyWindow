# 隐私窗口（PrivacyWindow）

> 鼠标指哪个窗口，哪个窗口清晰；屏幕上其余窗口实时盖一层毛玻璃。**不需要任何系统权限**，不上传任何内容。

macOS 菜单栏小工具。纯 Swift + AppKit 公开 API，单个 `swiftc` 命令即可构建，不需要 Xcode。

叫「隐私窗口」是因为它解决的是**旁边的人一眼看清你屏幕**的问题：办公室、咖啡店、屏幕共享时，只有你正在操作的那个窗口是清楚的。

### 快速开始

```bash
./build.sh run          # 构建并启动，菜单栏出现“眼睛划线”图标
```

把鼠标移到任意窗口上，其余窗口立刻盖毛玻璃；按 **⌥⌘P** 随时开关。想常驻使用，见下面的「安装」。

## 效果

| 鼠标在…… | 结果 |
|---|---|
| 某个普通窗口上 | 这个窗口清晰，同屏其它普通窗口盖毛玻璃 |
| 桌面空白处 / 菜单栏 / Dock | 按“鼠标在桌面”设置：全部模糊，或保持上一个窗口清晰 |
| 副屏的窗口上 | 只有副屏的窗口参与；主屏窗口全部模糊 |
| 全屏 App 里 | 该屏幕暂停覆盖（可关） |
| 开着「台前调度」时 | 全部暂停，避免和系统缩略图打架（可关） |
| 白名单 App 上 | 这个 App 永远清晰，也不被当作焦点 |
| 白名单反转开启时 | **只有**白名单里的 App 会被盖：鼠标移上去变清晰，和平时一样；列表以外的 App 一概不处理 |
| 黑名单 App 上 | 这个 App **永远模糊**，鼠标放上去也不会变清晰 |
| 你关掉的那块显示器 | 整块屏幕不覆盖 |

- **⌥⌘P** 随时开关毛玻璃（可以改键，也可以关掉）。
- 悬停即聚焦，**不用点击**。键盘焦点仍按 macOS 原生逻辑走，点击、拖拽、滚动完全不受影响（覆盖层忽略鼠标事件）。
- 清晰 / 模糊切换带淡入淡出（80–250 ms 可调），快速划过多个窗口时用防抖（0–100 ms）避免闪烁。
- 覆盖层按窗口圆角裁剪，只盖当前 Space 里的窗口；菜单栏、Dock、通知中心、控制中心永远不会被盖住。
- 关闭或退出时所有窗口立即恢复原样。

## 构建

只需要 Xcode Command Line Tools（`xcrun swiftc`）：

```bash
./build.sh            # → build/PrivacyWindow.app
./build.sh test       # 构建并跑 67 项自检
./build.sh run        # 构建并启动
./build.sh dist       # ad-hoc 签名 + build/PrivacyWindow.zip
./build.sh dmg        # ad-hoc 签名 + build/PrivacyWindow.dmg（带「应用程序」快捷方式）
```

系统要求 macOS 14+。`build.sh` 按本机架构编译；目前只在 Apple Silicon（arm64）上构建和测试过。

## 安装

在本机构建出来的 `build/PrivacyWindow.app` 可以直接双击打开，不用装到别处。想当作常驻工具用：

1. 把 `build/PrivacyWindow.app` 拖到「应用程序」文件夹（或个人的 `~/Applications`）。给别人装的话用 `./build.sh dmg` 打出的 `build/PrivacyWindow.dmg`：打开后把 App 拖进旁边的「应用程序」文件夹即可。
2. 先打开一次：菜单栏出现图标即可，没有 Dock 图标、不会弹授权请求。
3. 需要开机自启的话，**挪好位置以后再**在设置里勾上「登录时自动启动」。登录项记录的是 App 当时的位置，之后再挪动要重新勾一次。
4. 想从 Spotlight 打开设置或在 Finder 里看到它，把它留在「应用程序」里就行。

**升级**：重新构建，用新的 `PrivacyWindow.app` 覆盖旧的。设置存在用户偏好里（见上面「名称」表），不在 App 包内，覆盖后不会丢。

**拷到别的 Mac**：`./build.sh dmg` 打成 `build/PrivacyWindow.dmg`（`./build.sh dist` 则是 zip）。它**没有 Developer ID 签名和公证**，只做了 ad-hoc 签名，别的电脑第一次打开很可能被 Gatekeeper 拦下。可以到「系统设置 → 隐私与安全性」里找「仍要打开」；如果提示“已损坏”，在终端执行 `xattr -dr com.apple.quarantine /Applications/PrivacyWindow.app` 后再试。这条路径我只按惯例写，**没有在别的电脑上验证过**。另外 `build.sh` 按本机架构编译，给 Intel 机器用要在 Intel 机器上重新构建。

## 使用

启动后菜单栏出现一个“眼睛划线”图标，没有 Dock 图标。点开菜单：

- **关闭毛玻璃 / 开启毛玻璃** — 一键开关（即时生效，含淡出），后面显示当前快捷键
- **设置…** ⌘, — 打开设置窗口
- **退出隐私窗口** ⌘Q

第一次启动直接就能用，**不会弹出任何授权请求**。

### 设置项

| 设置 | 范围 / 选项 | 默认 |
|---|---|---|
| 材质 | 浅灰磨砂（HUD）· 明亮（全屏面板）· 轻透（弹窗）· 中性（标题栏）· 深色（窗口底衬） | HUD |
| 暗化 | 0 – 90 % | 25 % |
| 切换动画 | 80 – 250 ms | 150 ms |
| 焦点防抖 | 0 – 100 ms | 40 ms |
| 鼠标在桌面 | 全部模糊 / 保持上一个清晰 | 保持上一个清晰 |
| 快捷键 | 点一下按键框再按新的组合键；「⌫」清除，Esc 取消。要带 ⌘ / ⌥ / ⌃ / ⇧ 之一，或者用 F 键、方向键这类不会打出字符的键 | ⌥⌘P |
| 启用快捷键 | 关掉后快捷键不生效（设置仍然保留） | 开 |
| 全屏暂停 | 某块屏幕上有全屏 App 时，该屏幕暂停覆盖 | 开 |
| 「台前调度」开启时暂停覆盖 | 系统的台前调度开着时全部暂停 | 开 |
| 低性能模式 | 不用毛玻璃，只盖一层暗色遮罩（暗化至少 50 %，保证文字看不清） | 关 |
| 开机自启 | 登录时自动启动。本程序没有 Developer ID 签名和公证，系统可能要求你先去「系统设置 → 通用 → 登录项与扩展」里允许一次 | 关 |
| 显示器 | 每块显示器一个开关；插拔显示器后列表会自动更新 | 全部开启 |
| 白名单 | 永远清晰。列表 + 「添加…」/「移除所选」，也可以把 App 从 Finder **拖进列表**。勾上「反转」后含义变成**只给列表里的 App 盖毛玻璃** | 空 |
| 黑名单 | 永远模糊，鼠标放上去也不会变清晰。白名单反转时，黑名单只对同时也在白名单里的 App 生效 | 空 |

名单里是 App 的 bundle id（如 `com.apple.Safari`）。同一个 App 只会在其中一个名单里，加入一边会自动从另一边移除。

## 常见问题

| 现象 | 多半是什么原因 |
|---|---|
| 完全没有毛玻璃 | 菜单栏图标是“眼睛”而不是“眼睛划线” = 当前是关闭状态，点一下或按 ⌥⌘P。也可能：该显示器在设置里被关掉；这块屏幕上有全屏 App；系统的「台前调度」开着（默认全部暂停） |
| 某个窗口一直清晰、盖不上 | 它在白名单里；或者宽或高小于 80 pt；或者它不是普通层级的窗口（菜单、弹出面板、浮动小窗、输入法候选条）。白名单开了「反转」时，列表以外的 App 都不盖，这是设计如此 |
| 鼠标放上去也不变清晰 | 它在黑名单里（黑名单 = 永远模糊）；或者这块屏幕被暂停 / 关掉了 |
| 划过窗口边缘时来回闪 | 把「焦点防抖」调大一点（默认 40 ms） |
| 觉得不够“糊” | 系统材质的模糊程度都一样，只能加「暗化」；见「为什么是这样做的」 |
| 按快捷键没反应 | 「启用快捷键」被关了；或者这个组合被别的程序先占了（目前设置里**不会**提示占用，换个组合试试） |
| 开机自启没生效 | 勾选之后挪过 App 的位置 → 重新勾一次；或者系统在「登录项与扩展」里把它标成不允许 |
| 拖动窗口时毛玻璃慢半拍 | 已知限制：窗口位置靠约 16 ms 一次的轮询，拖动时滞后 1–3 帧 |
| 低性能模式只是变暗 | 设计如此：它用暗色遮罩代替毛玻璃来省电，暗化不低于 50 % |
| 想让某个 App 永远不被盖 | 加进白名单（把 App 从 Finder 拖进列表，或用「添加…」） |
| 只想盖某几个 App，别的不碰 | 把这几个 App 加进白名单，勾上「反转：只给列表里的 App 盖毛玻璃」 |

## 卸载

1. 勾过「登录时自动启动」的话，先在设置里取消勾选（否则登录项里会留一条失效记录；也可以到「系统设置 → 通用 → 登录项与扩展」里手动移除）。
2. 菜单栏 →「退出隐私窗口」，或按 ⌘Q。
3. 删除 `PrivacyWindow.app`。
4. 想连设置一起清掉：`defaults delete com.dalongxia2017.PrivacyWindow`。程序不在 App 包以外留任何文件。

## 为什么是这样做的

结论都来自调研和本机实测（macOS 27.2 / Apple Silicon）。同类产品和参考资料的原始链接在文末「同类与参考」。

**一句话：没有一模一样的现成项目。** 现有的工具都是“把非活动窗口变暗或模糊”，焦点跟着**键盘 / 前台 App** 走；跟着**鼠标悬停**走的没有先例，这是本项目的差异点。它同时是专注工具（只剩一处清晰）和防偷看工具（旁边的人看不清文字）。

### 最初的设想，哪些要调整

| 最初的设想 | 实际情况 | 现在的做法 |
|---|---|---|
| 模糊强度、暗化、材质风格都可调（轻磨砂 / 重模糊 / 暗色遮罩） | 系统材质的**模糊半径不可调**。7 种材质把同一张黑白条纹图的方差都压到 ≤ 11，差别只在色调和明暗 | 给“材质（色调）+ 暗化”两个选项，不叫“模糊强度”。连续半径只有私有 `CAFilter` 或截屏自算两条路 |
| 切换动画 120–180 ms 避免闪烁 | 方向对，但还要加**防抖**：鼠标划过窗口边缘和缝隙时会高频切换 | 焦点判定加 30–50 ms 防抖；动画期间旧焦点淡出、新焦点淡入并行 |
| 窗口移动时模糊层跟随，延迟低于 50 ms | 单次窗口列表 0.26 ms，余量很大 | 跟随时**关闭隐式动画**直接改位置；只有焦点切换才做 alpha 动画 |
| 读其他 App 的窗口信息可能需要屏幕录制权限 | **不需要**。窗口 id / 位置 / 大小 / 层级 / 所属进程都免费给，只有窗口**标题**受保护 | 不读标题，所以零权限 |
| 监听窗口移动可能需要辅助功能权限 | 轮询足够 | 60 Hz 轮询 |
| 毛玻璃用 `NSVisualEffectView` 比实时 Core Image 省电 | 正确，而且这是唯一零权限的方案 | 默认渲染路径 |
| 低性能模式用半透明暗色遮罩 | 0.45 黑遮罩下条纹方差仍有 4900（清晰是 16256），**文字依然可读** | 低性能模式保证暗化至少 50 %；它省电、能帮助专注，但挡不住刻意凑近看的人 |
| 鼠标在桌面空白处：全部模糊或保持上一个 | 可行，纯逻辑 | 两种都做，默认“保持上一个” |

### 悬停聚焦会“抖”

鼠标在两个窗口的边界，或者经过小窗口（Finder 工具面板、悬浮歌词、输入法候选条）时，焦点会快速变化。靠四件事压住：

1. **最小尺寸**：忽略宽或高小于 80 pt 的窗口（本机 10 个窗口里有 2 个小于 50 pt）。
2. **停留判定**：鼠标进入新窗口要停留一会儿才切换（防抖，默认 40 ms）。
3. **磁滞**：鼠标落到没有合法窗口的地方时，保持上一个焦点。
4. **白名单 / 黑名单**：把输入法、录屏、视频播放器这类 App 按 bundle id 固定下来。

### 四条技术路线，为什么选了 A

| 路线 | 能连续调模糊强度吗 | 需要什么权限 | 结论 |
|---|---|---|---|
| **A. 覆盖层 + `NSVisualEffectView`（公开 API）** | 不能，只能选材质 + 暗化 | **零** | **默认做法** |
| B. 私有 `CABackdropLayer` + `CAFilter` | 能 | 零 | 以后做成默认关闭的实验开关。系统升级可能失效，不能上 Mac App Store |
| C. ScreenCaptureKit 截屏 + 自己算高斯模糊 | 能 | **屏幕录制**，系统更新后可能要重新授权 | 不做。权限和性能成本都最高，而且实测截到的画面和屏幕上真正合成出来的不一致 |
| D. 纯暗色遮罩 | — | 零 | 就是设置里的“低性能模式” |

路线 C 还有两个具体问题：`CGWindowListCreateImage` 在新 SDK 里已经不能用了（编译器提示改用 ScreenCaptureKit）；用 ScreenCaptureKit 的 `captureImage` 采样时，alpha 为 0 的覆盖层被采成纯色，同一块区域的基线方差两次运行分别是 1890 和 3586，不稳定。

### 几个实测出来的结论

测试方法：开一个黑白条纹（10 pt 间隔）的靶窗口，用系统 `screencapture` 截它内部算亮度方差。清晰 ≈ 16256，数字越低越看不清。

| 测了什么 | 结果 | 对产品的影响 |
|---|---|---|
| 7 种系统材质的模糊程度 | 方差全部 ≤ 11，区别只在色调和明暗（平均亮度 34–91） | **“模糊强度”滑杆做不出来**，只能给“材质 + 暗化” |
| 只盖 45 % 黑色暗化、不模糊 | 方差 4900，**文字仍然可读** | 低性能模式保证暗化至少 50 % |
| 读一次屏幕上的窗口列表 | 0.26 ms（10 个窗口） | 60 Hz 轮询完全够用，一帧有 16.7 ms |
| 读一次鼠标位置 | 0.0003 ms | 可以忽略 |
| 窗口矩形是否含阴影 | 不含（AppKit 尺寸和 `CGWindowList` 给的完全一致） | 按 bounds 贴毛玻璃不会压到阴影 |
| 没有录屏权限时能拿到什么 | 窗口 id、位置、大小、层级、所属进程都有，**只有窗口标题拿不到** | 本程序不读标题，所以不需要任何权限 |
| 屏幕上出现过哪些窗口层级 | 只有 `0`（普通窗口）、`24`（菜单栏）、`-2147483601`（通知小组件） | 只处理层级 0，菜单栏和 Dock 天然不会碰 |
| 覆盖层放在哪一层 | floating(3) + 1 = 4：高于所有普通窗口，低于 Dock(20) 和菜单栏(24) | 菜单栏和 Dock 不会被盖 |

各材质的原始数据：HUD 方差 11 / 平均亮度 91；全屏面板 6 / 83；弹窗 5 / 75；标题栏 1 / 73；窗口底衬 1 / 58；菜单 2 / 66；表单 0 / 34；只暗化 45 % 4900 / 70。

### 设计上的取舍

- **焦点跟鼠标，不跟键盘。** 点击仍然按系统原生逻辑激活窗口，两个“焦点”互不干扰。
- **覆盖区域 = 被遮窗口的矩形 减去 压在它上面的所有窗口。** 否则被遮窗口伸到焦点窗口下面的那一截会把焦点窗口也糊掉——这是实测踩到的坑。
- **窗口移动时直接改位置、不做动画；只有焦点切换时才做淡入淡出。** 跟随要快，切换要柔。
- **圆角不压阴影。** 窗口矩形不含阴影，所以按矩形贴毛玻璃、用圆角遮罩裁边即可。
- **只看当前 Space。** 窗口列表本身只返回当前桌面上的窗口，切换桌面后自动重算，不用额外监听。
- **全屏 App 所在的那块屏幕整个暂停**，避免全屏视频和游戏被盖。
- **台前调度开着时直接暂停**，不和系统的缩略图打架。只读系统偏好里的开关，不需要权限。
- **连续模糊强度**如果要做：私有 `CAFilter` 只能是默认关闭的实验开关，失效要能退回公开 API；叠多层毛玻璃来模拟“更糊”效果有限、GPU 成本线性增加，不推荐。

## 它做了什么、没做什么

**做了**

- 每块屏幕一个全屏透明覆盖层窗口（`NSVisualEffectView` behind-window 模式），鼠标事件全部穿透。
- 每帧（60 Hz）读一次鼠标位置和窗口列表（`CGWindowListCopyWindowInfo`，约 0.26 ms），取最上层被鼠标命中的普通窗口当焦点。
- 被遮窗口的覆盖区域 = 窗口矩形 减去 压在它上面的所有窗口矩形，所以被遮窗口伸到焦点窗口下面的部分不会把焦点窗口也糊掉。
- 分屏（Split View）：两个窗口各占半块屏幕，不会被当成全屏；鼠标在左边就只盖右边，反之亦然。
- 台前调度（Stage Manager）：读系统偏好里的开关（只读，不需要权限），开着时默认全部暂停。
- 全局快捷键（Carbon `RegisterEventHotKey`）、开机自启（`SMAppService`），都不需要权限。
- 只处理 layer 0、宽高都 ≥ 80 pt、可见的窗口。设置面板自身、菜单栏、Dock、通知等一律不碰。

**没做（有意）**

- 不申请辅助功能、屏幕录制、任何权限。`CGWindowListCopyWindowInfo` 不需要授权就能给出窗口 id、位置、大小、所属进程；只有窗口**标题**需要录屏权限，而本程序根本不读标题。
- 不截屏、不读窗口内容、不联网。
- 不修改、不移动、不置前任何别人的窗口。
- 不用私有 API（`CAFilter` / `CABackdropLayer` 那条能连续调模糊半径的路留作以后的实验开关）。

## 已知限制

- 模糊强度只能在这 5 种系统材质里选，不能连续调——公开 API 就这么多（几种材质的模糊程度其实一样，只是色调不同）。
- 窗口在屏幕上的位置靠轮询（约 16 ms 一帧），拖动窗口时覆盖层会滞后 1–3 帧。
- 台前调度只做了“开着就暂停”，没有在它的界面里继续工作；分屏是按规则自然支持的，没有写专门代码。
- 快捷键被别的程序占用时不会生效，设置窗口里**目前不会提示**（错误信息已经能拿到，只是没显示出来，见下一步计划第 10 项）；程序本身不会抢。
- 没有图标（菜单栏用的是 SF Symbol）。
- 没有做 Developer ID 签名 / 公证，发给别人需要对方在「隐私与安全性」里放行；开机自启也可能需要先在系统设置里允许一次。
- 只在 Apple Silicon + macOS 27.2 上测过。Intel 机型和 macOS 14–26 还没验证，重点要看的 macOS 14 上 `SMAppService` 和 `NSVisualEffectView` 的行为是否一致。

**还没验证的**（自动化测不了，或要换个环境）：

| 项 | 现状 |
|---|---|
| 圆角遮罩的裁剪效果 | 已赋值，没有人目视确认过 |
| 焦点切换的体感速度 | 逻辑上 16 ms 轮询 + 150 ms 淡入；自动化只量了结果，没量体感 |
| 多桌面 Space、真实全屏 App、真实台前调度、真实分屏 | 基于 API 语义推断。台前调度只用了“注入开关”的方式测过，没在系统真开着时跑 |
| 没有录屏权限的账户 | 本机终端有录屏权限，无法复现；程序自身不申请，理论上不受影响 |
| 私有 `CAFilter` 在 macOS 27 上还能不能用 | 没测。做实验开关之前要先用 MaterialView 的代码单独探针 |

## 需要你手动确认的两件事

自动化测试没法代替这两件事，各花一分钟：

1. **开机自启**：设置里勾上「登录时自动启动」，注销再登录，看菜单栏图标有没有出现。程序没有 Developer ID 签名和公证，系统可能要你先去「系统设置 → 通用 → 登录项与扩展」里允许一次。
2. **快捷键**：按 ⌥⌘P 看毛玻璃有没有开关；在设置里点按键框改成别的组合再试；关掉「启用快捷键」后确认按键不再生效。

把 App 拖进名单和「添加…」对话框已经手动试过，没问题。

## 下一步计划

按建议的先后顺序排，每项写清楚为什么。

### 1. 模糊强度真正可调

**问题**：5 种材质的模糊程度几乎一样（实测方差都是 1–6），只差色调，用户调不了“更糊一点”。

- **先做预设（公开 API，安全）**：把“材质 + 暗化”组合成几档，比如“轻 / 中 / 重”，重的档位暗化更高。成本低，但本质是靠暗化，不是靠模糊。
- **再做实验开关（私有 API，有风险）**：`CABackdropLayer` + `CAFilter` 可以连续调模糊半径，做法见文末 MaterialView。系统升级后可能失效，不能上 Mac App Store。要做成默认关闭的“高级”开关，失效时自动退回公开 API。

### 2. 降低拖动窗口时的滞后

**问题**：窗口位置靠轮询，拖动时覆盖层滞后 1–3 帧。零权限下拿不到“窗口移动了”的通知（那需要辅助功能权限）。

- 用 `CVDisplayLink` 代替 `Timer`，让轮询对齐屏幕刷新，少掉最多一帧的抖动。
- 窗口列表有变化时立即重算一次，不等下一帧。
- 实测 4K / 多显示器下每帧耗时，必要时只重算鼠标所在屏。

### 3. 空闲降频，省电

鼠标和窗口都不动时，把 60 Hz 降到 10 Hz 左右；一有变化立刻恢复。对笔记本电池有帮助。

### 4. 鼠标在桌面空白处时的细节

现在鼠标在桌面上时，桌面上露出的部分不受影响。可以加一个“桌面图标也模糊”的选项（在桌面区域再放一块覆盖层）。

### 5. 屏幕共享 / 录屏时自动全模糊

这是“隐私窗口”最值钱的场景：开视频会议时，别人只该看到你正在讲的那个窗口。

**要先确认**：检测“当前是否在屏幕共享”需不需要权限。Hush 用的是私有 CGS API，GhostLayer 做的是让覆盖层在共享画面里隐藏（见文末）。如果需要权限，就做成可选功能，默认不申请。

### 6. 应用图标

现在只有菜单栏的 SF Symbol。设置窗口和 Finder 里的图标是空白。

### 7. 签名与公证

Developer ID 签名 + 公证。做完之后别人下载就能直接打开，开机自启也不会被系统拦。

### 8. 兼容性验证

- Intel 机型（`build.sh` 已经按本机架构编译，换机器直接跑就行）。
- macOS 14 / 15 / 16 / 26 各跑一遍自检和端到端。
- 重点看 macOS 14：`SMAppService` 和 `NSVisualEffectView` 的行为是否一致。

### 9. 自动更新

Sparkle。等有了签名再做，否则更新包校验没有意义。

### 10. 快捷键注册失败时在设置里提示

**问题**：快捷键被别的程序占用时，程序只是静默不生效，用户不知道为什么。错误信息其实已经拿到了（`HotKeyController.errorDescription`），只是设置窗口没有显示。

在设置窗口的快捷键那一行下面显示一行红字即可，顺便把它列进 `selfcheck`。

### 更远的想法（都需要权限，暂时不做）

- “只模糊含敏感内容的窗口”：要读窗口标题或用辅助功能接口。
- 录屏时强制全模糊：要先解决上面第 5 项的检测问题。

### 做过但决定不做的

- **真实点击穿透的自动化测试**：本机没有辅助功能权限，注入不了点击。而且覆盖层一有鼠标经过就会让出位置，实际使用中没有影响，所以不做。

- 第二轮：最小程序（焦点毛玻璃、设置、菜单栏、开关）。

## 测试

```bash
./build.sh test                         # 67 项纯逻辑自检：坐标换算、窗口过滤、命中、防抖、区域减法、暂停规则、名单、快捷键、设置读写
python3 spike/smoke.py --all            # 端到端：真实覆盖层 + 截图验证（见下）
```

`smoke.py` 会启动一个黑白条纹的靶窗口和本程序，用系统 `screencapture` 截靶窗口内部算亮度方差——清晰 ≈ 16256，被毛玻璃盖住 < 10。它用 `--mouse` 调试参数指定“虚拟鼠标”位置，**不会挪动你的真实光标**；但测试的大约 1 分钟里你屏幕上的窗口会真的被盖毛玻璃。需要 Pillow（`python3 -m pip install Pillow`）。

| 检查 | 验证的是什么 |
|---|---|
| focus × 5 种材质 | 鼠标不在靶上 → 模糊；移到靶上 → 清晰；退出 → 清晰 |
| toggle off / on / both ways | `--disable` `--enable` `--toggle` 即时生效，并量延迟上界 |
| low power uses dim mask | 低性能模式下靶窗口被暗化到看不清（方差 2500–6000），悬停后清晰 |
| disabled screen is left alone | 设置里关掉的显示器上不放覆盖层 |
| stage manager pauses overlay | 台前调度开着时全部暂停 |
| settings window / menu bar icon | 设置窗口上屏且尺寸正确；状态栏按钮挂到了菜单栏窗口上 |
| settings layout / fits on screen | 设置内容没有被窗口裁掉，窗口高度放得进屏幕 |
| per-screen switches | 每块显示器都有一个开关，默认全开 |
| launch at login off by default | 默认不写登录项 |
| hotkey registered / can be turned off | 快捷键默认已注册；关掉后不再注册 |
| overlay follows window | 靶窗口每 1.2 s 跳一个位置，覆盖层跟着走，并量滞后上界 |
| overlay ignores mouse | 所有覆盖层窗口都 `ignoresMouseEvents` |

端到端里**没有**覆盖的（需要人工点一下）：把 App 拖进名单和「添加…」对话框、按快捷键、开机自启（登录后真的会启动）。
